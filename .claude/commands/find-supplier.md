# /find-supplier

リサーチシートの商品画像から 1688 の同款を画像検索し、上位3件を仕入先候補として登録する。

## 前提

1688 はヘッドレスでは開けない（`验证码拦截` で遮断される）。
**必ず claude-in-chrome（ユーザーのログイン済み Chrome）を使う。**

**Amazon 側（`/rival-research`）は playwright に移したが、ここは移さない**（2026-09-05 にユーザー判断）。
Amazon の中間ページはボタンを押せば通るのに対し、1688 のキャプチャは**通過を代行できず**、
ユーザーに手動で解いてもらう必要がある。ログイン済みブラウザを共有する形でないと成り立たない。

1商品あたり5〜8手、サイズ表を見る場合は10手前後かかる。**件数を先にユーザーへ伝えること。**
57件回して数時間かかった実績がある。**1セッションでの上限は20件前後**（理由は後述
「連続実行するとキャプチャで止まる」）。超える件数は分割して伝える。

## 連続実行するとキャプチャで止まる

2026-08-30〜31 に54件を実処理した際、3回発生した。

| 回 | 状況 | 復旧 |
|---|---|---|
| 1回目 | 20件連続で処理した直後 | タブ作り直し・3分待機・8分待機のいずれも効かず（計11分）、ユーザーの手動通過が必要 |
| 2回目 | 1件ごとに14秒間隔を空けて23件処理した後 | 5分・7分・10分待っても解けず、手動通過が必要 |
| 3回目 | 手動通過の後、わずか3件処理した時点 | 同上 |

**間隔を空けても防げない。** 14秒間隔でも23件で再発し、3回目は3件で発生した。
1688 は累積アクセス量で判定しているとみられ、セッションを通じた総件数が増えるほど
発生しやすくなる（間隔を空けたほうが持ちはする。1回目の20件連続より2回目の23件のほうが長く保った）。
商品と商品の間は**30秒以上**を目安に空ける。

**時間では解けない。** 3分・5分・7分・8分・10分・11分と待ったが、いずれも解けなかった。
**待つのは無駄。** キャプチャが出たら、次の順で対処する。

1. タブを作り直して開き直す（1回だけ試す）
2. 解けなければ**即座に**ユーザーへ手動通過を依頼する。**キャプチャの通過は代行できない。**
   通過を待つ間、以降の行は処理を止める

### 実施計画の立て方

54件を1セッションで回すのは現実的でない。**1回のセッションで20件前後を上限**とする。
それを超える件数は、日をまたぐか、ユーザーが在席していて手動通過を頼める時間帯に実施する。
着手前に件数を伝える際（下記「前提」）、この上限を踏まえて何回に分けるかも合わせて伝える。

## Step 1: 対象行を出す

```bash
.venv/bin/python find_supplier.py targets --sheet "<シート名>" --limit 10
```

購入先が空で画像がある行だけが返る。0件なら終了する。
各行に `title`（Amazon商品名。`TITLE_SELL` 列）が含まれる。**この title がサイズと個数の判断材料になる。**

### 対象が0件でも、行が空とは限らない

`targets` は**画像がある行しか返さない**。ASIN列にURLだけ入っていて商品名も画像も空の行は、
まだ商品情報を取っていないので対象外になる。その場合は先に取得する。

```bash
.venv/bin/python fetch_products.py --sheet "<シート名>" --count-only   # 未取得の行数を数える
.venv/bin/python fetch_products.py --sheet "<シート名>" --limit 3      # 上から3行だけ取得
```

**行番号は指定できない。** シート先頭から未取得の行を順に処理するので、
目的の行が何番目かを `--dry-run` で確かめてから `--limit` を決める。

### `targets` はシート名が変わると落ちる。標準エラーを捨てない

2026-08-30 に「自動調査」タブが価格帯で分割され、「自動調査1000円以下」「自動調査1000円-2000円」
のようにリネームされた。作業中にシート名が変わると `find_supplier.py targets` は
`WorksheetNotFound` で落ちる。

**`2>/dev/null` を付けて叩くとこのエラーが握りつぶされ、空の JSON が返るだけになって
原因が分からなくなる。** 標準エラーは必ず表示させること（親リポジトリの規約にも
「`2>/dev/null` で標準エラーまで捨てるのは不可」とある）。シート名は毎回スプレッドシートで
現物を確認してから渡す。

### 行番号は毎回ずれる

シートは他のジョブが行を挿入・アーカイブするため、**前回の行番号は当てにならない。**
**書き込む直前に `targets` を取り直し、商品名で行番号を引く。**

2026-08-28 に1行ずれており、`write` の「対象行には既に購入先が入っている」ガードが
無ければ**別商品に書き込んでいた。** 記憶した行番号を使ってはいけない。

2026-08-30 にも実例が出た。`B0GWHLSL67`（日傘）を行31に書き込んだ直後、別の行が挿入されて
行32へずれ、空いた行31には別商品（`B0GQMGZW48` 紳士傘）が来た。**毎回 `targets` を取り直して
ASIN で引いていたため取り違えを免れた。**

### ブランド品は着手前に除外する

日本・韓国ブランドの化粧品やライセンス品は 1688 に同款が存在しない。検索する前に
`targets` の結果（`title`）から落とす。2026-08-30 は61件中7件がこれだった
（Yunth ユンス、イニスフリー、VT スポットパッチ、たまごっち用ケースなど）。

## Step 2: 行ごとに画像検索する

各行について次を繰り返す。

1. 画像を作業ディレクトリへ落とす

   ```bash
   curl -s -o <scratchpad>/<ASIN>.jpg "<image_url>"
   ```

2. 検索ページを開く（`mcp__claude-in-chrome__navigate`）

   ```
   https://s.1688.com/youyuan/index.htm?tab=imageSearch
   ```

3. ファイル入力を探す（`mcp__claude-in-chrome__find`、`file input for uploading a local image`）
   **ref は毎回取り直す。** ページ遷移で無効になり、前回の ref では
   `Element ref not found` になる
4. `mcp__claude-in-chrome__file_upload` で画像を投入する
5. **9秒待ってから、JS でボタンをクリックする**（後述「クリックは JS で送る」）
6. 10秒待つ
7. `scripts/extract_candidates.js` の中身を `mcp__claude-in-chrome__javascript_tool` で実行する
8. **候補が商品として妥当か見る**（後述「合わない候補は書かない」）
9. **サイズ別価格を取る**（後述「価格は最安サイズのもの」）
10. **数量倍率を判定する**（後述「1688は個数単価、Amazonはセット」）
11. 書き戻す

    ```bash
    .venv/bin/python find_supplier.py write --sheet "<シート名>" --row <行番号> --asin <ASIN> --candidates <JSONファイル>
    ```

    候補の JSON は次の形。**`spec` に規格表で選んだ規格名をそのまま入れる。**

    ```json
    [{"offerId": "801382389275", "title": "耐高温加厚防滑透明硅胶垫片",
      "company": "広州市旺拓包装", "province": "広東",
      "spec": "白色半透明", "price": 4.79, "quantity": 1}]
    ```

    **`spec` は価格が取れなくても書く。** URL だけ入れる場合（構成が揃わないとき）でも、
    どの規格を見て「揃わない」と判断したのかが後から追えるようにする。

    **`--asin` を必ず付ける。** 対象行の ASIN が一致しなければ書き込まずに止まる。
    行番号だけを頼りにすると、他のジョブが行を挿入・削除したときに別商品へ書く
    （2026-09-05 に `fetch_products` が同じ理由で8行ずれた）。

## 手数を減らす（browser_batch でまとめる）

1商品ごとに navigate / wait / click / wait / extract を個別に呼ぶと**7〜8往復**かかる。
`mcp__claude-in-chrome__browser_batch` は複数アクションを1回で順に実行できるので、
**アップロード後の「待機→クリック→待機→抽出」は1回にまとめる。**

```
browser_batch actions:
  1. computer        wait 9      （アップロードの反映を待つ）
  2. javascript_tool div.search-btn へイベント列を送る
  3. computer        wait 10     （検索結果の描画を待つ）
  4. javascript_tool extract_candidates.js
```

4番の戻り値が候補JSONになる。**待機を削ってはいけない**（9秒・10秒とも実測値。
短くすると検索が走る前に抽出して空配列が返る）。

navigate と file_upload は前段でまとめる。1商品あたり**3往復**まで減る。

**`find` を `browser_batch` に混ぜてはいけない。** `Permission denied for reading pages
on this domain` で失敗する。`find` は単体で呼べば通る。新しいタブへの `navigate` も
単体呼び出しでないと `Navigation to this domain is not allowed` になることがある。
Step 2 の手順が「navigate → find → file_upload → batch」と分かれているのはこのため。

**`extract_candidates.js` の戻り値に URL を含めてはいけない。** `location.href` を
含めて返すと `[BLOCKED: Cookie/query string data]` でブロックされる。候補の配列だけを返すこと。

## クリックは JS で送る

「搜索图片」ボタンは **`div.search-btn`**。`find` で得た ref のクリックも座標クリックも
**頻繁に空振りする**（ポップアップの再描画とウィンドウ幅の変動が原因）。座標クリックは
ポップアップの外に当たると閉じてしまい、アップロードした画像ごと消える。

JS でイベント列を直接送ると確実に動く。

```js
(() => {
  const b = document.querySelector('div.search-btn');
  if (!b) return 'no-btn';
  for (const t of ['pointerdown','mousedown','pointerup','mouseup','click']) {
    b.dispatchEvent(new MouseEvent(t, {bubbles:true, cancelable:true, view:window}));
  }
  return 'clicked';
})()
```

成功すると URL に `imageId=...` が付く。付いていなければ検索は走っていないので、
抽出しても空配列が返る。**URL を見て確認すること。**

## 規格は `spec` に残す（S列・AI列・AN列）

規格表で選んだ規格名を、そのまま候補の `spec` に入れる。シートでは各仕入先リンクの直後の
**『规格』列**へ書かれる（購入先=S、候補1=AI、候補2=AN）。

| 商品 | spec の例 |
|---|---|
| 排水口シリコン垫片 | `白色半透明` |
| ブラウン替刃 | `32B白盒包装` |
| 折りたたみハンガー | `黒色+夹子【独立包装】` |
| ピンバイス | `黑色手捻钻+10PC【袋装】` |

**規格名は中国語のまま写す。** 訳すと 1688 側で探せなくなる。
複数規格を足し合わせた場合（洗濯ネットのサイズ混在など）は `大50x60x2+中40x50x3` のように
内訳を書いておくと、後から検算できる。

**2026-09-09 まではこの列が無く、規格を `title` に混ぜて書いていた。** 過去の行は
`title` 側に規格が入っていることがある。

## 価格は最安サイズのもの

**検索結果カードに出る価格は、その商品の最安バリエーションの価格。**
サイズ違いで単価が数倍変わるので、そのまま使うと原価を大幅に過小評価する。

実例（磁石、`offerId=674948577389`、全116サイズ）:

```
F10*4*2mm   ¥0.12  ← カードに出る価格
F10*10*3mm  ¥0.39
F20*10*3mm  ¥0.62  ← Amazon側が 20×10×3mm ならこれが正しい（5倍差）
```

Amazon商品名にサイズが書かれている場合（`直径16mm` `20×10×3mm` `A3` など）は、
**候補の商品ページを開いてサイズ表から該当価格を取る。**

```
https://detail.1688.com/offer/{offerId}.html
```

を開いて9秒待ち、`scripts/extract_variants.js` の中身を `javascript_tool` で実行する。
**規格表のレイアウトは2種類ある。** スクリプトは表形式を試し、無ければ選択形式に落ちる。

| 形式 | 場所 | 見た目 |
|---|---|---|
| 表形式 | `[class*="sku"]` に `规格型号` の表 | 多規格（10〜100件） |
| 選択形式 | `module-od-sku-selection` | 少規格。`規格名 / ¥価格 / 库存n个` |

**選択形式には2種類ある。**「規格名 ¥価格 库存n」が並ぶものは全件読めるが、
**色などの選択肢だけが並び、価格は選択中の1件しか出さない商品がある。**
後者は規格名に `-` が入り、価格が1件しか取れないので**すぐ分かる**。

```
颜色 / 短款清洁刷 / 长款清洁刷 / 3件套 / 4件套 / 5件套 / 6件套   ← 価格が付かない
规格 / - / ¥0.53                                              ← 選択中の1件だけ
```

選択肢をJSでクリックしても React の状態が変わらず価格は更新されない（2026-08-28 に確認）。
**深追いせず別の候補を見る。** 同じ検索結果の中に全件読める商品がたいてい混ざっている。

**選択形式は規格が1件だけのことが多い。** その場合は入数が規格名に出る
（`滑轮固定垫1个` = 1個売り）ので、倍率の判断に使う。

**ページ本文を行単位で走査してはいけない。** おすすめ商品も「名前 ¥価格」の形で並ぶため、
規格ではなく別商品を拾う（2026-08-26 に発生）。

**価格セルは innerText を取ると価格と在庫が連結される**（`"¥4.1999898"` = ¥4.1 と在庫999898）。
葉ノードまで降りて `["¥4.1", "999898"]` に分けてから価格だけを取る。

選ぶときは**サイズだけでなく色・耐荷重も見る**。ステンレス製なら銀色、耐荷重10kgなら
それを満たす規格を選ぶ。規格に `拉力0-5.5kg` のように書いてあることが多い。

サイズ表が1件しか返らない商品（単一仕様）はカード価格をそのまま使ってよい。

### カード価格が「付属品だけ」の値段のことがある

サイズ違いだけでなく、**構成違い**で規格が並んでいることがある。
カードに出るのは最安構成なので、本体ではなく付属品の価格を拾うことがある。

実例（ピンバイス、`offerId=1043456394978`）:

```
10pc钻头【0.8-3.0】袋装        ¥1.4  ← カードに出る価格。ドリル刃だけで本体が無い
黑色手捻钻+10PC【袋装】        ¥5.4  ← Amazon側は本体+刃10本なのでこれが正しい（4倍差）
```

規格名に `+` が入っていたら構成の違いを疑う。`钻头`（刃）`手捻钻`（本体）のように
**部品名だけの規格**は本体を含まない。Amazon商品名の構成と突き合わせて選ぶ。

### サイズ表があっても照合できない商品がある

規格名が **型番や号数**で、寸法と対応しないことがある。実例:

```
自動車用リベット: 「1号」「2号」…「13号」  ← 穴径mmではない
                 「01553-09321」          ← メーカー品番
```

Amazon側が「8mm穴径」でも、`8号` は穴径8mmを意味しない。**当てはめてはいけない。**
この場合はカード価格のまま使い、倍率（個数）だけ適用する。
候補タイトルに `8毫米` のように寸法が書かれていればそれを優先する。

### 入数は規格名にも書かれている

規格名に `8个装`（8個入り）`【一个的单价】`（1個あたりの単価）と明記されていることがある。
**カード価格が1個あたりか袋単位かはここで判断できる**ので、サイズ表を開いたら必ず見る。

実例（椅子脚カバー16個入り）:

```
8个装             ¥1.07  ← 8個入りなので quantity 2
【一个的单价】     ¥1.8   ← 1個単価なので quantity 8（8個入り商品の場合）
```

### 1688のパックがAmazonの入数より多いときは按分する

最小単位が大きく、Amazonの1リスティングより多いことがある。
**パック価格 × (Amazonの入数 ÷ パックの入数)** を現地価格にし、倍率は1にする。

実例（手芸モール100本 `offerId=1030024203338`）:

```
全規格が「500根 ¥11」   → 100本相当 ¥2.2、倍率 1
```

倍率は正の整数なので `0.2` は使えない。**現地価格側で割る。**
規格名に元のパック数を書き添えておくと、後から見て按分したと分かる。

### サイズ混在のセットは規格ごとに足す

Amazon側が「大中小の詰め合わせ」の場合、倍率ひとつでは表せない。
規格表から各サイズの単価を引いて**合計を現地価格にし、倍率は1**にする。

実例（洗濯ネット8枚 `offerId=725621467189`）:

```
大 50x60 ¥1.7 × 2 = 3.4
中 40x50 ¥1.3 × 3 = 3.9
小 30x40 ¥1.1 × 3 = 3.3   → 現地価格 ¥10.6、倍率 1
```

同じ商品に `10件套` のような詰め合わせ規格があってもAmazon側と枚数構成が違うことが多い。
**構成が一致しない限り、単価を足して作る。**

### 構成が揃わないときは価格を書かず、URLだけ入れる

Amazon側が複数の部材をまとめた商品で、1688側が**その一部しか売っていない**ことがある。
足りない分を無視して部分的な価格を書くと、**原価が過小に出て利益が過大になる。**
手数料に 0 を書かないのと同じ理由で、これも書いてはいけない。

**候補の `price` を `null` にすると、URLだけ書いて価格欄は空のままになる。**

実例（造花セット = フローラテープ6巻 + 地巻ワイヤー50本）:
1688側の候補はテープのみでワイヤーを含む出品が無く、テープ分の ¥2.34 を書かずURLのみ記入した。

同じ理由で、**規格表を確認していない2件目・3件目の候補も `null` にしてよい。**
未検証のカード価格を入れるより空欄のほうが安全。

**規格表に色しか出ず、Amazon側が求める長さ・サイズが選べない商品もある。**
充電ケーブルで発生（規格が「白 ¥3」「苹果灰 ¥2.9」のように色違いのみで、
長さ 1M/2M が選べない型）。候補を複数開いても同じ構成だったので、
このときも価格は書かずURLだけ入れた。

## 1688は個数単価、Amazonはセット

1688 は個数単価で表示されることが多く（例: 磁石1個 ¥0.03）、Amazon側はセット単位で
売られている（例: 磁石300個入り）。このズレを埋めないと価格計算が実際の何百分の一にもなる。

Amazon商品名の `300個入` `4個セット` `5枚` `2足組` などを読み、1688の1件が
Amazonの1リスティングに対して何個分かを**候補ごとに**判断して `quantity` に入れる。

候補によって単位が違うことがある。実例（椅子脚カバー16個入り）:

```
硅胶椅子脚套          ¥0.61  ← 1個単価なので quantity 16
24pcs硅胶椅子脚套     ¥14.64 ← 24個入りなので quantity 1
```

**判断できない場合は `1` にする（推測で埋めない）。** 数式に `*1` が残るので、
後から見て判断に失敗した行だと分かる。

## 同種の商品は1回の検索を使い回す

画像が違っても、**Amazon側が同じ汎用品なら1688の供給元は同じ**ことが多い。
1件検索して規格表まで取れたら、その規格表から他の行の分も選べる。

| まとめた行 | 使い回した内容 |
|---|---|
| ピンセット4行 | 同一供給元の規格表から 9本セット・単品・カーブを選び分け |
| 布団用洗濯ネット2行 | 同一供給元の規格表から 90×110 と 80×80 を選び分け |
| ニッパー式爪切り3行 | 色違いのみで全規格同価格だったのでそのまま |

**使い回してよいのは、規格表に相手の仕様が載っているときだけ。**
「同じジャンルだから」で価格を流用しない。載っていなければ個別に検索する。

**別ASINなのに商品名が完全一致する行がある**（2026-08-30 は日傘2行）。
画像だけでなく `targets` の結果を商品名でも見比べ、一致するなら1回の検索結果を両方に書く。

2026-08-30〜31 の実例:

- **浮き輪4行**（`B0H3ZC2CXF` / `B0H3YYM4DY` / `B0H3ZBBFS7` / `B0H3Z3NL23`）は商品名が
  完全一致するサイズ違いで、**1回の検索**で4行すべてに書き込めた。しかも Amazon側のサイズ表記
  （`90#` `80#` `70#`）が1688の規格名と**同じ記法**だったため、価格を正確に振り分けられた
- **USB-Cケーブル**は、1件目で取得した規格表に「C-C 数据线【2米】¥3」が載っていたため、
  2件目は**検索せずに**その規格表から書けた

## 合わない候補は書かない

画像検索は**平面で無地のもの**と**形が汎用的なもの**を大きく外す。実績:

| Amazon商品 | 1688が返したもの |
|---|---|
| ステンレス板（磁石補助板） | 花束の包装紙 |
| マグネットシート | HDPE土工膜、児童用色画用紙 |
| スニーカー消しゴム | 文具の消しゴム |
| 歯ブラシケース（メッシュ） | メッシュのペンケース |
| ゴミ袋 45L | メラミンスポンジ |
| FAXインクリボン | 化粧筆、カッター |

当たり外れは**商品画像の性質**である程度予測できる。

| 画像の性質 | 結果 | 実例 |
|---|---|---|
| 商品そのものが写っている | **当たる** | 脱毛器、ハンディファン、おにぎり型、ラップカッター、傘 |
| パッケージ・箱が写っている | **外す** | 流せるトイレブラシ（箱）→ トイレ洗剤・防虫剤・セメント／ニキビパッチ（箱）→ スプーン・ヘアマスク |
| ボトル・チューブ | **外す** | ネイル接着ジェル → ハンドクリーム・アロエジェル |
| メッシュ状 | **外す** | 空調服ファンカバー → ヘアネット・使い捨てキャップ・水桶の防虫網 |

**候補のタイトルが別カテゴリなら、その行は書かずに次へ進む。**
57件中12件がこれに該当した。無関係な候補を埋めると、ユーザーが後で消す手間が増える。

3件揃わないときは**取れた分だけ書く**。1件でも `write` は動く。
無理に3件目を埋めるより空けておくほうがよい。

候補の並びは**Amazon側の特徴に合うものを先頭にする**。1688の検索順は関連度順ではない。

- 「回転式フック」なら `旋转挂钩` と明記された候補を優先
- 「スキミング防止」なら `防消磁` `防窥` を優先
- 「本革」なら `真皮` を優先

## 画像検索で当たらない商品（再検索しない）

下記は 2026-08-24〜25 に実際に検索して**別カテゴリが返ることを確認済み**。
結果は変わらないので、`targets` に出てきても検索せず飛ばす。

スチールプレート／マグネットシート／ブラジリアンワックス／顔すっきりテープ／

使い捨てサニタリーボックス（大理石柄）／ドーナツ型の布団用洗濯ネット／
石膏ボード用ピンフック

**「〜柄」の商品は素材そのものの商品が返る。** 大理石柄の紙製サニタリーボックスは、
天然大理石の花器・ペン立てが返る（4件とも同じ結果）。柄のプリントは形状の特徴として

**筒状のメッシュは養殖用の網カゴになる。** ドーナツ型の布団用洗濯ネットで発生。

**画像検索が外れた行は、消化する前に Step 3 の名称検索を試す。**

## Step 3: 名称検索で画像検索を補う

**主は画像検索（Step 2）。** 名称検索は次の3ケースでのみ使う補完・裏取り手段。

- 画像検索が外れたとき（上記「画像検索で当たらない商品」に挙がる、パッケージ写真・ボトル・
  メッシュなど平面/汎用形状の商品）
- 画像検索で選んだ候補が妥当かを**裏取り**したいとき
- 画像検索より**安い候補**を探したいとき（名称検索は1個単価売りの商品が上位に来やすい）

### 検索語は「実体」に直す。直訳では当たらない

商品名をそのまま訳しても外れる。**その商品が中国で何と呼ばれているか**に直す。
コツは「材質 + 形状 + 機能」で組み立てること。日本語の商品名にある販促語
（「ハンドメイドアクセサリーパーツ」「クリア」等）は落とす。

実例（`B0H4FWR5H7` 透明ヒートン100個セット / 貼り付けヒートン / カボション貼り付けパーツ）:

| 検索語 | 考え方 | 結果 |
|---|---|---|
| `贴片羊眼钉` | 「貼り付けヒートン」の直訳 | **外れ**。羊眼钉が付いた樹脂パーツばかり返る |
| `透明吊片自粘` | 透明・吊り片・自己粘着（**形と機能**で言い直す） | **的中**。1位が求めていた商品 |

**シートの「検索ワード」列（`NOTE_BUY_OTHER3`）は日本語のAmazon検索語なので、
1688 ではそのまま使えない。** 上記の要領で言い直す。

### URL は GBK でエンコードする（最重要）

```
https://s.1688.com/selloffer/offer_search.htm?keywords=<GBKでURLエンコードした語>
```

**UTF-8 でエンコードすると文字化けして0件になる。** 実際に `透明贴片羊眼钉` を UTF-8 で送ったら、
ページタイトルが `閫忔槑璐寸墖缇婄溂閽` になり商品が1件も返らなかった。

Python でこう作る。

```python
import urllib.parse
url = "https://s.1688.com/selloffer/offer_search.htm?keywords=" + urllib.parse.quote(keyword.encode("gbk"))
```

**成功したかはページタイトルで分かる。** 検索語がそのまま `透明吊片自粘_透明吊片自粘批发_…` と出ていれば正しい。
文字化けしていればエンコードが違う。

### 候補の抽出は画像検索と別スクリプト

画像検索の結果ページは React の内部状態から `offerId` を取る（`scripts/extract_candidates.js`）。
**キーワード検索の結果ページは DOM 構造が違い、そのスクリプトでは0件になる。**

キーワード検索では**リンクから取れる**。カードは `a.search-offer-item` / `.search-offer-wrapper` で、
`href` に `offerId=` か `offer/<数字>` が入っている。

```js
(() => {
  const items = [], seen = new Set();
  for (const card of document.querySelectorAll('a.search-offer-item, .search-offer-wrapper')) {
    if (items.length >= 12) break;
    const m = (card.getAttribute('href') || '').match(/(?:offerId=|offer\/)(\d{9,})/);
    if (!m || seen.has(m[1])) continue;
    seen.add(m[1]);
    const text = (card.innerText || '').replace(/\s+/g, ' ').trim();
    const pm = text.match(/¥\s*([\d]+)\s*\.\s*([\d]+)/);
    items.push({ id: m[1], t: text.slice(0, 50), p: pm ? parseFloat(pm[1] + '.' + pm[2]) : null });
  }
  return JSON.stringify(items);
})()
```

**価格は `¥ 0 .29` のように数字が分割されて入る**ので、正規表現で整数部と小数部を別々に拾う
（画像検索側の「価格セルは innerText を取ると価格と在庫が連結される」と同じ現象）。

抽出後の扱い（サイズ表で照合する・カード価格を信用しない・数量倍率を判定する・書き戻す）は
Step 2 と同じ。名称検索の候補も `find_supplier.py write` に渡す前に規格表で裏取りする。

### 画像検索の裏取りに使えた実例

`B0H4FWR5H7` は画像検索で `1031126018032`（透明吊片diy 自粘【100个】¥7.66）を選んでいたが、
名称検索（`透明吊片自粘`）でも**同じ商品が1位**に来た。選定の妥当性が独立した経路で裏づけられる。

同時に、名称検索でしか出てこない**より安い候補**も見つかった（`1080791169922` は同種の吊り片が
23規格あり、`透明闭口底9mm孔直径4mm` などが1個 ¥0.02＝100個で約¥2。画像検索の候補の2〜3倍安い）。
ただし**形状の一致を確認できないうちは価格を書かない**（上記「構成が揃わないときは価格を書かず、
URLだけ入れる」と同じ方針）。

## 注意

- **`imageAddress` パラメータで画像URLを渡してはいけない。** 画像は表示されるが検索結果が0件になる
- **キャプチャが出たら停止する。** 対処の順序は「連続実行するとキャプチャで止まる」を参照
- 検索結果が0件だった行は何も書かず、ASIN をログに残して次へ進む
- **同一画像の行はまとめる。** `targets` の `image_url` が同じ行は同じ商品なので、
  検索は1回で済ませて両方の行に同じ候補を書く
- 既に値が入っている列は `write` が自動でスキップする。
  「セルに既に値が入っているため一部の列への書き込みをスキップしました」は正常なログ
- 開いたタブは `mcp__claude-in-chrome__tabs_close_mcp` で閉じる
- **`write` が Google Sheets の 503 で落ちたら、再実行の前に対象行を読んで確認する。**
  途中まで書けている場合があり、そのまま再実行すると「既に値がある」でスキップされて
  歯抜けになる。2026-08-25 に発生（このときは未書き込みだったのでそのまま再実行した）
