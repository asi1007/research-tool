# /rival-research

与えられた ASIN と**ほぼ同一の商品**を Amazon の3経路から探し、順位とともにその ASIN 行の直下へ追加する。

ブラウザ操作は **playwright**（`rival_research.py collect`）が全部やる。claude が判断するのは
**どれがほぼ同一か**だけ。1 ASIN あたり CLI 3回、1〜2分。

## 手順

```bash
# 1. 3経路をブラウザで読む（商品ページ・検索結果・カテゴリランキング）
.venv/bin/python rival_research.py collect <ASIN> --out /tmp/rivals.json

# 2. 出力を見て「ほぼ同一」の候補だけ残した JSON を書く（下記）

# 3. 対象行の直下へ挿入
.venv/bin/python rival_research.py write <ASIN> --candidates /tmp/rivals.json --dry-run
.venv/bin/python rival_research.py write <ASIN> --candidates /tmp/rivals.json

# 4. 商品情報と数式を埋める
.venv/bin/python fetch_products.py --sheet "<シート名>" --limit <候補数>
.venv/bin/python fill_formulas.py --sheet "<シート名>"
```

`collect` は経路ごとの候補を順位付きで表示し、**自社 ASIN には `← 自社` を付ける**。
検索順位とランキング順位は**会話で必ず報告する**（ライバルとの相対位置がこの調査の主眼）。

## 何を「ほぼ同一」とするか

**同じ製品・ほぼ同じ仕様のものだけ拾う。** 同じ売り場に並ぶだけの商品は入れない。
判定材料は商品名（素材・形状・設置方法）。迷ったら**入れない**。

例（自社 = `歯ブラシスタンド ステンレス製 置き型 多機能`）

| 候補 | 判定 | 理由 |
|---|---|---|
| Luxspire 歯ブラシスタンド ステンレス製 置き型 | ○ | 素材・設置方法とも一致 |
| レック ステンレス 歯ブラシスタンド 置き型 | ○ | 同上 |
| 無印良品 白磁歯ブラシスタンド 1本用 | × | 素材が違う（磁器） |
| 山崎実業 フィルムフック 歯ブラシホルダー | × | 設置方法が違う（壁掛け） |
| IRETION 歯ブラシスタンド 珪藻土 | × | 素材が違う |
| マーナ 歯ブラシホルダー 吸盤付き | × | 設置方法が違う |

**カテゴリが同じでも素材・形状が違えば別物。** 上の例では検索12件のうち9件が脱落した。
**上位から3件ではなく、同一と判定できたものを上から3件。**

**入数違いは同一に含める。** アンブレラマーカーのようにセット数がバリエーション軸の商品では、
20個・25個・50個がすべて同じ棚で競合する。素材と付属金具（シリコンリング＋カニカン等）が
一致していれば入数が違っても拾う。

## 渡す JSON

`collect` の出力から**同一と判定した候補だけ**を残す。**順位は元の順位のまま**
（脱落したものを飛ばしても番号を詰めない。`関連4` は関連枠の4番目という意味）。

```json
{
  "関連":     [{"asin": "B0F1N7BCGY", "title": "...", "rank": 1}],
  "検索":     [{"asin": "B001FCMOHY", "title": "...", "rank": 3}],
  "ランキング": [{"asin": "B005N5PRO6", "title": "...", "rank": 9}]
}
```

**同一と判定したものは全部入れてよい。** 採用件数は `write --limit`（既定3）が経路ごとに絞る。
**採用件数から漏れた経路の順位もラベルには載る**ので、多く渡すほど情報が増える。
実例: `B0H6F8VSK9` は関連6位・検索5位。検索で採用され、ラベルは `関連6 / 検索5` になる。

## 書き込みの仕様

- 対象行の**直下**へ候補の数だけ行を挿入し、ASIN列と順位列に書く
- **同じ ASIN が複数経路に出たら1行にまとめる**（順位列へ改行区切りで併記）
- 並び順は経路順（関連→検索→ランキング）、経路内は順位順
- 自社 ASIN は候補から自動で外れる（検索・ランキングには自社も出るため）
- 順位列（列コード `RIVAL_RANK`、見出し『順位』）は **E列の次**。対象タブに無ければ `write` が自動で挿入する（冪等）

**`fetch_products` は1回で `--limit` 件までしか処理しない。** 埋まらない行が残ったらもう一度流す
（挿入直後は行数の把握が古く、初回で全部埋まらないことがある）。

**`fill_formulas.py` を必ず流す。** 挿入した行には月間販売高・利益・利益率の数式が入らない。

## Amazon は素の Chromium を通さない

`collect` の中で対処済みだが、仕組みを知らないと 0件が返ったときに詰まる。

- **「ショッピングを続ける」の中間ページが返る。** `data-asin` が1つも無い状態になる。
  ボタンを押すと**トップページへ飛ばされる**ので、通過後に目的の URL を開き直している
- **プロファイルを `~/Library/Caches/ms-playwright/research-amazon` に残している。**
  一度通過すれば Cookie が付き、次回以降は中間ページが出ない
- 0件が返ったら `--headed` を付けて実行し、実際に何が表示されているか見る

## API では代わりにならない

| 経路 | API | 使えない理由 |
|---|---|---|
| 関連商品 | — | 商品ページの推薦枠は SP-API にも Keepa にも無い |
| 検索結果 | SP-API `searchCatalogItems` | **カタログ検索順であって購買者向け検索順ではない** |
| ランキング | Keepa `/bestsellers` | 集計時点がずれる。トークンも要る |

## セレクタ（2026-09-05 時点で確認済み）

`src/infrastructure/rival_scraper.py` に集約。Amazon の DOM が変わったらここだけ直す。

| 経路 | 起点 | 順位の取り方 |
|---|---|---|
| 関連商品 | `#sims-simsContainer_feature_div_0` | `[data-asin]` の出現順 |
| 検索結果 | `div[data-asin][data-component-type="s-search-result"]` | スポンサー枠を除いた通し番号 |
| ランキング | `[id^="gridItemRoot"]` | `.zg-bdg-text` の `#N` |

- **関連商品はスポンサー枠と ID が別。** 広告枠は `#desktop-dp-sims_SponsoredProductsSimsDpDesktop` で、
  見出しは同じ「この商品に関連する商品」。`#sims-simsContainer_feature_div_0` だけを見れば広告は混ざらない
- **検索結果はスポンサー枠を除いてから数える。** 除かないと順位が実際より下にずれる
- **ランキングの URL は商品ページの `pd_zg_hrsr` リンクから取る。** カテゴリIDを推測してはいけない
- ランキングは1ページ30件。`--depth` は既定12
